# Правила смысловых свойств («кому подходит») — каталог 0.4.0

Документ можно править: сервер и сборка каталога читают те же правила, что описаны здесь (реализация: `v040_build.py`). Агент **не должен** выдавать выведенные оценки за заявления бренда. У каждого свойства есть происхождение (`provenance`) и уверенность (`confidence`).

## Происхождение (`provenance`)

| Код | Когда ставим | Что обязательно указать |
|---|---|---|
| `brand_stated` | Бренд прямо написал это на сайте (нагрузка, тег «Couples», «Back pain relief», «Cooling», «Hand side-stitching» и т.п.) | Цитата или поле-источник (`source` / `quote`) |
| `derived_rule` | Оценка по правилам ниже из технических характеристик | Текст правила (`rule`) |
| `from_reviews` | Оценка опирается на отзывы покупателей | Число подтверждающих отзывов (`supporting_review_count`) |

Если есть и заявление бренда, и отзывы, основным остаётся `brand_stated`, а отзывы добавляются в `supporting`. Если заявления нет, но есть **не меньше двух** согласованных отзывов, основным становится `from_reviews`. Иначе — `derived_rule`.

Уверенность: 0.3 — мало данных или группа сравнения маленькая; 0.55 — правило по неполным характеристикам; 0.7 — правило по полным данным; 0.85 — заявление бренда; до 0.9 — заявление + подтверждающие отзывы. Для `from_reviews` уверенность растёт с числом отзывов (2 → 0.5, 5+ → 0.75).

Шкала позиций и пригодности: `poor` (0–0.33), `ok` (0.34–0.66), `good` (0.67–1.00). В выдаче агенту нужно называть и метку, и происхождение: «хорошо для сна на боку (выведено по правилу: жёсткость 4–6 и зональная поддержка), не заявление бренда».

## 1. Диапазон веса спящего (`sleeper_weight_kg`)

- Если у модели указана максимальная нагрузка на одного (`max_load_per_sleeper_kg`) с квалификатором `up_to` — верхняя граница **заявлена брендом**. Нижняя граница при этом выводится правилом.
- Квалификатор `over` означает «выдерживает более X кг»: верхняя граница не фиксируется, в подписи пишем «от X кг и выше (заявлено брендом)». Нижняя — X, если иное не следует из правил.
- Детские модели: ориентир 10–40 кг (ясли/toddler) или до заявленной нагрузки, если она есть; учитывается `recommended_age`.
- Вывод по жёсткости и конструкции (взрослые), если нагрузки нет:

  | Средняя жёсткость (1–10) | Рекомендуемый диапазон, кг |
  |---|---|
  | ≤ 3.5 (мягкий / plush) | 40–80 |
  | 3.6–6.5 (средний) | 55–110 |
  | 6.6–8.0 (жёсткий) | 70–130 |
  | ≥ 8.1 (очень жёсткий) | 80–150 |

  Для тонких матрасов (< 18 см) верхняя граница снижается на 15 кг. Для высоких (≥ 28 см) или с зональным блоком / плотным пружинным блоком верхняя граница поднимается на 10 кг.
- Человек весом W «подходит», если `min ≤ W ≤ max` (при открытой верхней границе достаточно `W ≥ min`).

## 2. Позы сна (`sleep_positions`: side / back / stomach / combination)

Правила вывода (можно уточнять):

- **На боку (`side`)**: хорошо, если жёсткость 4–6.5 **и** есть хотя бы одно из: зональная поддержка, memory foam, латекс в комфортном слое, euro top / pillow top / plush. Средне — та же жёсткость без этих признаков, или 6.6–8 с мягким топом. Слабо — очень жёсткий (≥ 8.1) без мягкого топа или очень мягкий (≤ 3) без поддержки плеча.
- **На спине (`back`)**: хорошо при жёсткости 5–8, ещё лучше при зональной поддержке или «orthopedic» в названии/тегах. Слабо при очень мягком (≤ 3.5).
- **На животе (`stomach`)**: хорошо при жёсткости ≥ 7; средне при 5–7; слабо при < 5 (таз проваливается).
- **Комбинированный сон**: `good`, если хотя бы две позы `good`, или одна `good` и вторая не ниже `ok`. Иначе — максимум `ok`, если две позы хотя бы `ok`.

Отзывы могут поднять или опустить оценку позы, если в тексте явно говорится о сне на боку / спине / животе.

## 3. Изоляция движений партнёра (`motion_isolation`)

- Хорошо: memory foam (visco), латекс в комфортном слое, независимый пружинный блок (pocket / micropocket), тег бренда «Couples».
- Средне: гибрид с пружинами, но без пены с эффектом памяти / латекса.
- Слабо: зависимый пружинный блок (Bonnell / continuous coil), если он указан.
- Отзывы про «partner / husband / wife / tossing / movement / isolation» учитываются как `from_reviews`.

## 4. Любители жёстких и мягких матрасов (`firm_lovers`, `soft_lovers`)

- `firm_lovers`: хорошо при макс. жёсткости ≥ 7 или ярлыке hard / firm / extra firm; средне при 5.5–7; слабо ниже 5.5.
- `soft_lovers`: хорошо при мин. жёсткости ≤ 4 или ярлыке soft / plush; средне при 4–6; слабо при ≥ 7 без мягкой стороны (двусторонние soft+firm считаются подходящими и тем и другим — берём соответствующую сторону).

Это вывод по шкале бренда, а не измеренная жёсткость.

## 5. Спящие, которым жарко (`hot_sleepers`)

- Хорошо, если бренд заявил охлаждение (`cooling: true`, тег Cooling, gel, phase change) или в комфортном слое есть латекс / шерсть / «breathable».
- Средне: пружинный блок без заявлений об охлаждении (воздух проходит лучше, чем у цельной пены).
- Слабо: memory foam / visco **без** заявления об охлаждении или геле.
- Отзывы «hot / sweat / cool / heat» могут сменить происхождение на `from_reviews`.

## 6. Боль в спине / ортопедия (`back_pain_orthopedic`)

- `brand_stated`, если в названии, тегах или описании есть orthopedic / orto / «back pain relief» / medical.
- Иначе вывод: хорошо при зональной поддержке и жёсткости 5–8; средне при ортопедических материалах без зональности; слабо при очень мягком матрасе без поддержки.
- Не обещать лечебный эффект. Формулировка для агента: «позиционируется как ортопедический» или «выведено по конструкции, это не медицинское заявление».

## 7. Для пары (`couples`)

Хорошо, если одновременно:

- изоляция движений не ниже `ok`, и
- в линейке есть размер от 160 см (queen+) **или** это двусторонняя модель с разными сторонами (duo) для разных предпочтений, и
- либо бренд пометил модель тегом «Couples».

Тег «Couples» — `brand_stated`. Иначе — `derived_rule`. Детские модели: `poor` (не для пары).

## 8. Край матраса (`edge_support`)

- `brand_stated`: «hand side-stitching», reinforced edge, «edge support» в описании или флаге `edge_support`.
- Иначе: средне-хорошо для tight top на независимых пружинах; слабее для высокого pillow / euro top без усиления края; неизвестно — не завышать (макс. `ok` с низкой уверенностью).

## 9. Индекс «цена / качество» (`value_for_money`)

Сравниваем только внутри сопоставимой группы:

- та же аудитория (взрослые / детские);
- тот же тип конструкции (`construction_type`);
- тот же диапазон жёсткости: мягкий ≤ 4, средний 4.1–6.5, жёсткий ≥ 6.6 (для двусторонних берём сторону, ближнюю к группе).

Цена — текущая (со скидкой) за размер **160×200**, если он есть у модели; иначе за самый частый общий размер в группе; иначе за минимальную взрослую цену в наличии.

Спецификация (баллы): +1 охлаждение, +1 зональность, +1 латекс, +0.5 memory foam, +1 гарантия ≥ 10 лет, +0.5 высота ≥ 25 см, +0.5 натуральные наполнители (шерсть, хлопок, койра, натуральный латекс), +1 независимые пружины / micropocket.

`index = (медиана цены группы / цена модели) * (1 + 0.2 * (баллы модели − средний балл группы) / max(средний балл, 1))`

Округляем до 2 знаков. Метки: `< 0.80` ниже среднего, `0.80–1.20` как в группе, `> 1.20` выгоднее группы. Если в группе меньше 3 моделей, уверенность ≤ 0.4, в подписи указываем малый размер группы. Индекс **всегда** `derived_rule`, никогда не выдаётся за оценку бренда.

## 10. Отзывы и выжимка «плюсы / минусы»

- Если отзывов 0 — так и писать: «на сайте бренда на дату сбора отзывов покупателей нет». Не выдумывать.
- Выжимка строится только из текстов и полей «достоинства / недостатки». Пункт попадает в плюсы или минусы, если его прямо подтверждают отзывы; рядом указывается число таких отзывов.
- Фото только исходными URL (Askona: `content.askona.ae/upload/...`, TMS: `review-images.judgeme.com/...`). Файлы не копируем к себе.
- Автор — имя или имя и инициал фамилии, без email и телефона.
